## 1. 文書の目的

本書は、Web記事のURLを入力すると本文を音声に変換し、スマートフォンでポッドキャストのように再生できるアプリのMVP要件を定義する。開発・受入判断の共通基準とし、将来機能はMVPの対象から分離する。

## 2. プロダクト概要

### 2.1 背景

ユーザーが読みたい記事を、移動中や作業中など画面を見られない状況でも聴けるようにする。MVPでは高度な編集や推薦ではなく、記事を最後まで音声で聴けるという中核価値を検証する。

### 2.2 MVPのゴール

ユーザーが記事URLを入力し、変換完了後に生成された音声を再生でき、画面ロック中またはアプリがバックグラウンドにある状態でも聴き続けられること。

### 2.3 成功条件

- 対象サイトの一般的な公開記事について、URL入力から音声再生まで完了できる。
- 再生中にアプリをバックグラウンドへ移しても音声が継続する。
- 変換失敗時に、ユーザーが次の行動を判断できるエラーを表示する。
- 最大10人のテスターへAndroid Preview APKまたはiOS TestFlightで配布し、核となる利用フローを検証できる。
- 対応対象の日本語記事において、URL入力から再生可能になるまでの成功率80%以上を目標とする。
- 正常に取得できる3万文字以内の記事の90%以上が、生成開始から5分以内に再生可能になることを目標とする。
- 月額総費用を1万円以内に維持する。

## 3. 想定ユーザーと利用シーン

### 3.1 想定ユーザー

- 公開Web記事を読む時間が不足している個人ユーザー
- 移動中、家事中、運動中などに記事を音声で消化したいユーザー
- MVP段階では開発者本人および招待した少人数のテスター

### 3.2 代表的な利用シーン

1. ブラウザで読みたい記事を見つけ、URLをコピーする。
2. アプリを開いてURLを貼り付け、音声生成を開始する。
3. 生成完了を待ち、記事タイトルを確認して再生する。
4. 端末をロックする、または別アプリへ移動して聴き続ける。

## 4. スコープ

### 4.1 MVPに含む機能

- `http` / `https` の記事URL入力
- URLと取得先の安全性検証
- 公開Webページの取得
- 記事タイトルと本文の抽出
- 読み上げに必要な最小限のテキスト整形
- 長文の分割およびTTSによる音声生成
- MP3ファイルの保存と配信
- 生成状態の表示
- 記事タイトルの表示
- 音声の再生、一時停止
- バックグラウンドおよび画面ロック中の再生
- 生成・取得・再生失敗時のエラー表示と再試行
- テスター向けアプリ配布

### 4.2 MVP対象外

- 会員登録、ログイン、複数端末同期
- プレイリスト、お気に入り、推薦
- LLMによる要約、脚本化、会話形式、複数話者
- ブラウザの共有メニューからの直接取り込み
- RSS、Kindle、Pocketなどとの連携
- 音声や記事の一般公開・共有
- 決済、課金、広告
- 管理画面
- App Store / Google Playでの一般公開

### 4.3 MVPの機能境界

MVPでは、1回につき1記事を生成し、再生・一時停止する機能だけを提供する。生成履歴、再生位置保存、15秒送り戻し、シーク、倍速、オフライン保存は対象外とする。アプリのプロセスが終了した場合、現在の記事状態を復元することは保証しない。

## 5. 業務・利用フロー

### 5.1 正常フロー

1. ユーザーがアプリを起動する。
2. 記事URLを入力する。
3. アプリが入力形式を検証し、音声生成APIへ送信する。
4. サーバーがURLを安全性検証し、HTMLを取得する。
5. サーバーがタイトルと本文を抽出し、読み上げ用に整形する。
6. サーバーが本文を必要に応じて分割し、TTSで音声化する。
7. サーバーが生成音声と最小限のメタデータを保存する。
8. アプリが変換完了を検知し、記事タイトルと再生操作を表示する。
9. ユーザーが音声を再生する。
10. バックグラウンドまたは画面ロック中も再生が継続する。

### 5.2 代替・異常フロー

- URL形式が不正: 送信せず入力エラーを表示する。
- 接続先がローカル・プライベートネットワーク等: サーバーが拒否する。
- ページを取得できない: HTTP状態やタイムアウトに応じたエラーを表示する。
- ログイン必須、ペイウォール、動的描画等で本文を抽出できない: 非対応である旨を表示する。
- 本文が空または上限超過: 変換を中止し理由を表示する。
- TTS生成が失敗: エラーを記録し、ユーザーに再試行手段を示す。
- 音声が見つからない: 再生成またはURL再入力を促す。

## 6. 機能要件

優先度は Must / Should / Could で示す。

| ID    | 機能                 | 要件                                                                          | 優先度 |
| ----- | -------------------- | ----------------------------------------------------------------------------- | ------ |
| FR-01 | URL入力              | ユーザーは記事URLを入力・編集できる                                           | Must   |
| FR-02 | 入力検証             | 空欄および非HTTP(S) URLをクライアント側で拒否する                             | Must   |
| FR-03 | 生成開始             | 有効なURLをサーバーへ送信し、一つの変換処理を開始できる                       | Must   |
| FR-04 | 重複操作防止         | 生成中の連打による同一リクエストの多重実行を防ぐ                              | Must   |
| FR-05 | URL安全性検証        | サーバーはSSRF対策としてスキーム、ホスト、解決先IP、リダイレクト先を検証する  | Must   |
| FR-06 | 記事取得             | タイムアウトとサイズ上限を設けて公開ページを取得する                          | Must   |
| FR-07 | 本文抽出             | ページから記事タイトルと主要本文を抽出する                                    | Must   |
| FR-08 | テキスト整形         | 不要な空白、ナビゲーション、URL等を除き、読み上げ可能なプレーンテキストにする | Must   |
| FR-09 | 長文分割             | TTSサービスの制限を超える本文を段落境界等で分割する                           | Must   |
| FR-10 | 音声生成             | 抽出本文を単一話者の音声に変換する                                            | Must   |
| FR-11 | 音声保存             | 生成音声を再起動・再デプロイで消えない領域に保存する                          | Must   |
| FR-12 | 状態表示             | 少なくとも「待機」「変換中」「再生可能」「失敗」を表示する                    | Must   |
| FR-13 | タイトル表示         | 抽出できた記事タイトルを表示する                                              | Must   |
| FR-14 | 音声再生             | 生成音声を再生・一時停止できる                                                | Must   |
| FR-15 | バックグラウンド再生 | アプリのバックグラウンド移行および画面ロック後も再生を継続する                | Must   |
| FR-16 | 音声配信             | 識別子に対応するMP3をHTTPS経由で取得・ストリーミングできる                    | Must   |
| FR-17 | エラー表示           | ユーザー向けの簡潔な原因と再試行方法を表示する                                | Must   |
| FR-18 | 再試行               | 失敗後に同じURLまたは修正したURLで再試行できる                                | Must   |
| FR-19 | 対象外: 生成履歴     | MVPでは生成済み記事の一覧を保存・表示しない                                   | 対象外 |
| FR-20 | 対象外: 再生位置保存 | MVPではアプリ終了後の再生位置を保存しない                                     | 対象外 |
| FR-21 | 対象外: 拡張再生操作 | MVPでは15秒送り戻し、シーク、倍速を提供しない                                 | 対象外 |
| FR-22 | 対象外: オフライン   | MVPでは音声を端末へ永続保存しない                                             | 対象外 |

## 7. 非機能要件

### 7.1 性能・容量

- UI操作に対する視覚的な応答は原則1秒以内に開始する。
- 音声生成中は処理中であることを継続表示する。
- 記事本文は3万文字を上限とする。
- HTML取得サイズは5MB、リダイレクトは最大3回、取得処理は全体30秒を上限とする。
- 生成ジョブは5分を上限とし、超過時は失敗として終了する。
- 想定テスターは最大10人、同時生成は最大2件とする。
- 月間TTS入力は500万文字を上限とし、上限到達時は新規生成を停止する。

### 7.2 可用性・復旧

- MVPでは24時間365日の可用性保証やSLAを設けない。
- 一時的な外部API・通信障害は、処理を失敗状態にして再試行可能にする。
- MP3はRailway Volumeに保存し、アプリケーションの再デプロイで失われないようにする。
- MP3と生成メタデータは作成から24時間保存し、その後自動削除する。
- MVPでは音声ファイルのバックアップを行わない。削除・消失時は再生成する。

### 7.3 セキュリティ

- 通信は本番・テスト配布環境ともHTTPSを使用する。
- TTSのAPIキー等の秘密情報はFastAPI側の環境変数に保存し、Expoアプリへ埋め込まない。
- URL取得時にlocalhost、ループバック、プライベートIP、リンクローカル、非HTTP(S)スキーム等を拒否する。
- DNS解決後およびリダイレクトごとに接続先を再検証する。
- HTML取得量、本文量、リダイレクト回数、処理時間に上限を設ける。
- ログへ記事本文、秘密情報、不要な完全URLを記録しない。
- テスター共通のMVPアクセスキー、IP単位のレート制限、月間文字数上限を併用する。アプリ内の共通キーは強固な秘密ではなく、一般公開前に正式な認証へ置き換える。

### 7.4 プライバシー・法務

- MVPはユーザー自身が私的に聴く用途を前提とする。
- 音声の一般公開・第三者共有機能は提供しない。
- 元記事のタイトルとリンクを確認可能にする方向とする。
- 対象サイトの利用規約、robots方針、著作権、TTS提供元の利用条件を確認する。
- 記事本文を保存する場合は保存目的、期間、削除方法を定める。

### 7.5 互換性・アクセシビリティ

- 対象OSはAndroidとiOSとし、Android 10以降およびiOS 15以降の実機を対象とする。
- 主要操作にはテキストラベルを付け、十分なタップ領域とコントラストを確保する。
- 画面読み上げ向けのアクセシビリティラベルを設定する。

### 7.6 運用・監視

- リクエストID、処理段階、結果、所要時間、エラー種別を記録する。
- 秘密情報や記事本文はログに含めない。
- Railway上で起動失敗、5xx増加、Volume容量を確認できるようにする。
- TTS利用量と概算費用を把握できるようにする。

## 8. データ要件

MVPではサーバーDBを使用せず、音声ファイルとJSON等の最小限のメタデータで管理する。

| データ         | 主な項目                                                  | 保存先               | 保存期間               |
| -------------- | --------------------------------------------------------- | -------------------- | ---------------------- |
| 生成メタデータ | ID、元URL、タイトル、状態、作成日時、失効日時、エラー種別 | Railway Volume       | 24時間                 |
| 音声           | IDに対応するMP3                                           | Railway Volume       | 24時間                 |
| 記事本文       | TTS処理中の一時データ。恒久保存は原則避ける               | メモリまたは一時領域 | 処理完了まで           |
| 端末データ     | 現在処理中または再生中の1記事の状態                       | アプリメモリ         | アプリプロセス終了まで |

## 9. 外部サービス・制約

- モバイル: React Native + Expo + TypeScript
- 対象: Android 10以降、iOS 15以降、日本語の一般公開記事、日本語音声
- ビルド・配布: EAS Build。AndroidはPreview APK、iOSはTestFlightで配布
- API: FastAPI
- ホスティング: Railway
- 永続ファイル: Railway Volume（例: `/data/audio`）
- 記事抽出: Pythonの `trafilatura` を使用し、FastAPI内で完結させる。
- 音声生成: Google Cloud Text-to-Speech、`ja-JP-Wavenet-A`、MP3。音質確認で問題がある場合は同価格帯の日本語WaveNet音声へ変更可能とする。
- ソース管理: GitHub

### 9.1 TTS選定理由と費用枠

Google Cloud Text-to-Speechの日本語WaveNetは、自然さと低価格のバランスを優先して採用する。2026-08-05確認時点の公式料金では、WaveNet音声は月400万文字まで無料、その後は100万文字あたり4米ドルである。料金や無料枠は変更される可能性があるため、リリース前および毎月、[公式料金ページ](https://cloud.google.com/text-to-speech/pricing?hl=ja)を確認する。

- 月間TTS上限: 500万文字
- 総費用上限: 月額1万円
- 警告水準: 月額見込み8,000円
- Railway、Google Cloud、EAS等の合計見込みが8,000円に達した場合は新規利用を抑制し、1万円を超える前に生成を停止する。
- 為替変動と各サービスの最低料金・従量料金を考慮し、TTS無料枠だけを前提にしない。

## 10. 受入条件

| ID    | 受入条件                                                                                                        |
| ----- | --------------------------------------------------------------------------------------------------------------- |
| AC-01 | 有効な公開記事URLを入力すると、処理中表示を経て記事タイトルと再生操作が表示される                               |
| AC-02 | 再生を開始すると、音声が記事本文の内容として理解可能に再生される                                                |
| AC-03 | 再生中にホーム画面へ戻る、別アプリへ移る、画面をロックする操作を行っても再生が継続する                          |
| AC-04 | 一時停止後に再生を再開できる                                                                                    |
| AC-05 | 不正URL、内部ネットワーク向けURL、本文抽出不能、TTS失敗、音声未検出の各ケースでクラッシュせずエラーが表示される |
| AC-06 | Google Cloudの認証情報がアプリ配布物やクライアント通信に露出しない                                              |
| AC-07 | FastAPIを再デプロイしても、保存期限内の生成済みMP3を取得できる                                                  |
| AC-08 | Android 10以降の実機へPreview APK、iOS 15以降の実機へTestFlightで配布・インストールできる                       |
| AC-09 | 3万文字を超える記事はTTSを呼び出す前に拒否され、月間500万文字を超える新規生成も停止される                       |
| AC-10 | 作成から24時間を過ぎたMP3とメタデータが自動削除される                                                           |

## 11. リリース方針

1. 固定MP3でバックグラウンド・ロック画面再生を実機検証する。
2. ローカル環境でURL取得、本文抽出、TTS、再生の一連を検証する。
3. FastAPIとVolumeをRailwayへ配置する。
4. Expoアプリに環境別API URLを設定し、EAS Previewビルドを作成する。
5. 少人数テストを実施し、核となるフローと失敗率を評価する。

## 12. リスク

| リスク                                | 影響                 | 初期対応                                                |
| ------------------------------------- | -------------------- | ------------------------------------------------------- |
| サイトごとのHTML差異で本文抽出に失敗  | 音声化できない       | 対応サイトを限定し、失敗理由を表示する                  |
| 動的描画・ログイン・ペイウォール      | 記事取得不能         | MVP非対応として明示する                                 |
| 長文TTSの時間・費用増大               | UX悪化、費用超過     | 文字数上限、分割、タイムアウト、利用量監視              |
| バックグラウンド再生のOS・端末差異    | 中核価値が成立しない | Android 10以降とiOS 15以降の実機で固定MP3を先行検証する |
| アプリ配布物内の共通キー流出とAPI乱用 | 費用・障害           | 少人数配布、IPレート制限、月間文字数上限                |
| 著作権・サイト規約                    | 利用停止・法務リスク | 私的利用、非共有、原文リンク表示、対象制限              |
| Volume単体の障害・容量不足            | 音声消失             | 保存期限、容量監視。成長後はS3/R2へ移行                 |

## 13. 確定した前提・推奨値

- MVPは一般公開ではなく、最大10人のテスターによる検証用とする。
- Android 10以降およびiOS 15以降を対象とする。
- 日本語の一般公開記事と日本語音声のみを対象とする。
- URLの貼り付け入力だけを提供する。
- LLMによる要約・脚本化は行わず、抽出本文を軽く整形して単一話者で読む。
- 1記事の生成、再生、一時停止だけを提供し、履歴や再生位置を保存しない。
- Google Cloud Text-to-Speechの `ja-JP-Wavenet-A` を使用する。
- サーバーDBは導入せず、Railway VolumeにMP3と最小限のメタデータを保存する。
- 3万文字、5分、同時2件、月間500万文字、24時間保存を上限とする。
- 月額総費用は1万円以内とし、8,000円を警告水準とする。
